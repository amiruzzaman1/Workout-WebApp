# Workout WebApp: project context for Claude

Personal workout, food and habit tracker. Built for Amir (complete beginner, trains at Jetts Newtown, Wellington NZ) and one friend. Each has their own account and plan. Not published to app stores. Web first; Android/iOS later via Expo Go.

## Stack
- Expo SDK 57, expo-router, React Native Web, TypeScript. Run: `npm run web` (clean cache: `npx expo start --web -c`). Build: `npx expo export --platform web` (output: dist).
- Supabase (auth + Postgres). Project ref `zglxidulxgjfschsrvqm`, URL https://zglxidulxgjfschsrvqm.supabase.co. Client uses the publishable key in `src/lib/supabase.ts`. Never use or commit the service_role key.
- Every table has RLS: `(select auth.uid()) = user_id`, granted to `authenticated` only (automatic table exposure is off). Full schema with versioned sections v1 to v10 in `supabase/schema.sql`; append new changes as a new vN section.
- Hosting: Vercel project `workout-webapp` (vercel.json has SPA rewrite). GitHub repo amiruzzaman1/Workout-WebApp, pushed from GitHub Desktop.
- Shared foods (v10, table shared_foods): foods users add by hand are visible to every signed in user, anyone can edit them, the database records who added and who last edited (trigger), only the creator can delete. The app shows Added or Edited by you or someone else, your own first, with a caution warning on user added foods. Duplicates by name are allowed.
- Data sources: free-exercise-db (public domain images), Open Food Facts (NZ barcodes and search, `src/lib/off.ts`). Web BarcodeDetector for scanning (Chrome/Android; iOS Safari falls back to typing the barcode).
- Avoid adding native libraries without telling the user to install them; `react-native-svg` is in package.json and installed, and the Dashboard summary rings use it (LineChart is still plain Views).

## Routes (tab bar must stay visible on every page, so detail pages live in per tab Stacks)
- Detail pages use one slim header, src/components/StackHeader.tsx (Back lined up with the page content, optional title, headerRight such as Edit). Every tab Stack layout passes stackOptions. The main AppHeader already covers the safe area, so never add another top inset.
- app/_layout.tsx: root Stack + Gate (no session -> /login; no profile -> /welcome)
- app/login.tsx: Forge logo, Sign in / Create account. A new password must pass src/lib/password.ts (8 or more characters, lowercase, uppercase, number, symbol, not your email or an easy word or repeated character), with a live strength meter and checklist on the Create account tab; Sign in accepts any existing password. Change password: User settings, app/(tabs)/user/password.tsx, checks the current password with verifyPassword() (one plain request to the login address, never a second client and never signOut because that ends every session) and skips that box for Google only accounts. Shared checklist: src/components/PasswordHelp.tsx. This is only the app side of password strength: the Supabase project (set by the user in Authentication, Sign In / Providers, Email) must also have a minimum length of 8 and required character types, because the app check can be bypassed. Forgot password by email is deliberately not built yet (the user may add it later); it would need the Supabase redirect URLs set.
- app/welcome.tsx: basic details for a new account (name, sex, date of birth, height, weight, goal weight), then /user/onboarding?new=1 for training days and plan. The logo is src/components/Logo.tsx; the icon PNGs (assets and public) are drawn to match it.
- app/(tabs)/_layout.tsx: one AppHeader above every tab (profile icon, app name Forge with barbell logo, day picker). The picked day is store.date and every page saves and shows records for that day (food, workouts, sleep, weight, water, time). The pill says Today, Yesterday or a weekday, never a date; dates appear only inside the dropdown. Muscle group icons: src/components/GroupIcon.tsx. Tabs: each with its own accent colour pill: (home) Dashboard (the Today screen was renamed), food, progress, time, library (Exercises), you
- (home): index (Dashboard: coach card with tough love or praise from src/lib/coach.ts; every group has a big white heading in the display font, 18px, with a coloured icon (Section with the big prop; other pages keep the small uppercase heading). The whole app uses one type scale (TYPE in src/lib/theme.ts), biggest first: app name 28 (the header name and logo are always the biggest thing), page title H1 22, section heading 18 (also H2), sub heading 16 (workout title, coach title, quote), body 14, small 12, labels 10. Big number readouts (timers, calories) are capped at 24 so they never beat the app name; the header name is 28 (26 only below 340px wide). Only the login splash shows the name larger (40). Sizes that depend on the screen (rings, coach picture, coach picker) come from usePageWidth() in ui.tsx (window width capped at PAGE_MAX 720, minus the 20px gutters), never fixed pixels, so it fits from a 320px phone up to a desktop, in this order: Your coach, Nutrition and water (rings), Your progress (tiles), Your day (24 hour chart), Today's Quote, then the selected day's workout last), week (whole week plan, notes, rebuild plan; not on the Dashboard), workout/[day]/[idx]?date= (logs against that date; gym timer only for today), (live workout, gym timer, rest timer, warm up + working sets, stopwatch for timed sets), session/[day]/[idx] (session editor, metric Reps/Seconds/Minutes)
- food: index (daily log, macros, water, meal summaries), add (search, scan, my foods, quick add, portion with % of daily targets), nutrition (body stats, BMI, burn breakdown, calorie and macro targets). A food's `unit` is `g`, `ml`, or `piece` (a whole item counted as 1, 2, 3, such as a kebab or a slice, no weight needed); Quick add has a By weight / Whole item choice, and By weight also has a g/ml/kg/L choice for the label's numbers (kg and L are converted down to per 100 g/ml on save, so storage never changes). The Portion screen mirrors this: a piece food asks "How many?" with whole item chips, a weight food keeps its g/ml amount box but can switch to kg/L next to it (the number shown converts, so 500 g becomes 0.5 kg). Sugars and saturated fat are not separate amounts, they are part of carbs and fat (the label's "of which" lines), so Quick add draws each as a smaller, indented `SubField` connected to its Carbs or Fat box with a corner line and labelled "optional", instead of sitting in a plain grid where it would look just as required as the macro above it; fibre and sodium (not part of anything else) stay in the separate "More nutrition" collapsible. `scaleFood()` and `fmtAmount()` in src/lib/nutrition.ts are unit aware; never scale or display a Food or FoodEntry's amount without them.
- Recipes and usuals (food/recipes.tsx list, food/recipe.tsx builder, table recipes, schema v13): a recipe is a list of ingredient lines (amount in g, ml, tsp, tbsp, cup or piece, NZ measures 5, 15 and 250 ml) with each ingredient's nutrition copied in when saved, so the total (and per serving) is worked out automatically and never changes if a food is edited later. A usual (the milk you always have) is just a one ingredient recipe, made with "Save this amount as my usual" on the portion screen. A recipe becomes a Food through recipeToFood() in src/lib/recipes.ts: per serving as a whole item (unit piece), or per 100 g with a serving size when a cooked weight is entered. Shown first in Search on the add screen, in My foods, and on the Food tab button. Built in lists, bundled offline in src/data and built by scripts/build-food-data.py (not run by the app): ingredients.json (87 curated ingredients from USDA FoodData Central SR Legacy, public domain, with spoon and piece weights so oil, salt and spice calories fill in from a tsp or tbsp), dishes.json (1,014 South Asian dishes from the Indian Nutrient Databank, Jaacks et al., open access CC BY, values per 100 g and per serving), bdfoods.json (379 Bangladeshi foods from the Food Composition Table for Bangladesh, INFS University of Dhaka 2013, via FAO INFOODS; Bengali names are searchable; no sugars or saturated fat in that source). src/lib/foodData.ts searches them; keep the source credit visible on the add screen.
- library: index, exercise/[id], machine/[key], machines, custom-exercise
- tracker.tsx: Tracker tab (sleep card + time tracker + a 24 hour donut of the day, also shown on the Dashboard). Time tracker (DayTrackers.tsx): pick a category (built in plus your own, saved in profiles.time_categories), type what you are doing (suggestions from past tasks in that category), then Timer, From and to, or Minutes. One entry per task per category per day: new time is added to it. activity_logs.segments (v11) keeps each from and to block; the minutes column is the total and holds the already logged time while a continued task runs, so the clock continues from it. Entries have a pencil Edit button (EditEntry in DayTrackers.tsx, opens in place: name, category, each from and to block with TimeField, and extra minutes without times; saving rebuilds minutes and segments) and a Continue button (today only) and the day's gym visits show with start and end times. (timer stores only started_at in activity_logs, so it keeps running with the screen locked or device off until Stop; useRunningTimer in DayTrackers.tsx; Dashboard shows a strip while it runs)
- tracker/tasks.tsx: the Tasks page, reached from a button at the top of the Tracker (the Tracker is now a folder with its own Stack: index.tsx and tasks.tsx). Tasks are planned for the day picked in the header (table tasks, schema v12: title, category, target_minutes, done, done_at). Ticking one keeps it and animates a Keep style box fill, tick pop and a line drawn through the title (TaskRow, honours reduce motion); it can be unticked. The time tracker never shows a tick box, it only lists that day's tasks as "Planned" suggestions above the recent names while typing (choosing one fills the name and category), and the Tasks page shows time tracked against a task with the same name that day.
- progress.tsx: tabs Weight (weigh ins, waist, trend chart with goal line, history), Food (7/30 day report), Training (workouts, gym time, lifts, adjust next time), Sleep (sleep averages, time tracker by category)
- user: index (User page: avatar, log out, streak, settings list with icons, goals, nutrition goals, training), onboarding (profile + body stats at sign up). Profile photo: tap the avatar (web and Android both use the same picker, expo-image-picker, which works on both without extra code) to pick a square photo from the gallery; uploadAvatar()/removeAvatar() in src/lib/store.tsx save it to the avatars Storage bucket as <user id>/avatar.jpg (overwritten each time, a ?t= tag on the URL busts the cache) and set profiles.avatar_url. No photo yet shows initials, same as before. Schema v14 (supabase/schema.sql) adds the column and the bucket with its policies (each user can only write their own folder, anyone signed in can read); this needs to be run by hand in the Supabase SQL editor, the connector that could run it earlier in this project is no longer connected.

## Key files
- src/lib/store.tsx: all app state and Supabase CRUD (profile, plan, logs, gym visits, food, water, sleep, activities, weights). Logging a newer weight updates profile.weight_kg.
- src/lib/planner.ts: plan generator (splits, two a day, goals incl. recomp), personalised warm ups per session focus, 5 to 9 exercises per session, timed holds.
- src/lib/progress.ts: double progression suggestions (add weight at top of rep range on all sets; 10% lighter after two sessions below range), gym visit helpers.
- src/lib/nutrition.ts: Mifflin St Jeor BMR; burn = BMR x 1.2 + work kcal (weekly hours x job MET x kg / 7) + training kcal; goal weight drives deficit/surplus; recomp 0.4%, muscle 0.5%, fat loss 0.75% bodyweight a week; protein 2.2 g/kg recomp, 2.0 lose, 1.9 muscle, 1.6 general; 1200 kcal floor. Fibre, sugars and saturated fat are calculated the same way as protein/carbs/fat, from your own calorie target (fibre 14 g per 1000 kcal; sugars and saturated fat each capped at 10% of calories, the WHO and NZ Heart Foundation guidance), so they change with your body details and goal. Sodium is a flat 2300 mg population safety limit (NZ Ministry of Health) that does not change with body size. Fibre is a goal (more is good); sugars, saturated fat and sodium are limits (staying under is the healthy range) shown with `limit` on NutrientMini, which flips the colour to A.over past the target. src/components/NutrientMini.tsx is the shared small nutrient readout with a hover bar, used on the Dashboard and the Food tab; both must stay in sync, since the user asked for these to show in both places.
- src/lib/theme.ts: C (pure black monochrome), F (Space Grotesk display, Inter body), A (muted accents: protein blue, carbs amber, fat violet, fibre green, water cyan, core rose, cardio orange, over red), GROUP_COLORS per muscle group.
- src/lib/quotes.ts + src/data/quotes.json: gym friendly quotes filtered by tag, random on each load and every 10 minutes, author shown. src/components/Dashboard.tsx: Dashboard summary card of solid SVG rings (carbs, fat, protein, cal, water) plus tiles.
- src/lib/tracker.ts + src/components/DayTrackers.tsx: sleep and time tracker (categories Study, Work, Project, Admin, Rest, Other). Times of day are always shown and typed in 12 hour AM/PM (the user does not want 24 hour): TimeField (src/components/TimeField.tsx) is a box for the hour and minutes plus an AM|PM toggle and hands back the saved 24 hour "HH:MM"; show times with fmt12() or clockOf() from tracker.ts, never raw. Storage stays 24 hour so old data and the sleep maths keep working.
- Hover, focus and icons (src/components/ui.tsx): every Pressable style function uses `hovered(state)` and the `smooth` transition, so buttons, chips, cards, list rows and links react to the mouse. New Pressables should do the same. `Button` takes `icon` (Ionicons name), `tint` (icon and hover border colour) and `label` (for icon only buttons). `Section` takes `icon` and `color`. `IconBadge` is a tinted rounded icon square. `Input` highlights its border on focus. public/index.html has the global keyboard focus ring and dark scrollbars. src/lib/meals.ts gives each meal its icon and colour. Delete buttons use a trash icon, not a cross. Hover tooltips: every bar, chart and ring shows a small white label with its value and a percentage on hover (and on tap on a phone). HoverTip wraps a plain bar or ring (align keeps the label off the screen edge); for something that is already pressable (a water glass, a tile) do not wrap it, use the useTip hook on the Pressable itself, because a wrapper around a Pressable never gets the web hover. TipBubble is the label, BarChart takes a reference (goal and label) and LineChart points take a note. Do not add a new bar or chart without one. Choices that each have their own colour (Tracker categories, Library muscle groups) use AccentTile, and list rows with an accent colour (exercises, calories and time by task) are cards, both with a 2px coloured line along the top like the Streak and This week tiles and the Progress stats; do not go back to left colour bars or pill chips for these. The bottom tab bar uses the same tiles (TabTile in app/(tabs)/_layout.tsx): each tab is a card with its own colour along the top, tinted when it is the current tab.
- Coaches: two characters the user picks between, saved on the device only (src/lib/coachStyle.ts, AsyncStorage key forge.coach). They are opposites and must stay that way. Goku (male, assets/Goku.png) is aggressive: he insults effort, bruises the ego and rage baits to push harder. Mirko (female, assets/Mirko.png) is soft spoken, calm, emotionally available and motivating: she pushes with care and belief, never with shouting or insults (the user chose this on purpose, even though the anime character is a loud fighter). Both pictures are the user's own images of existing anime characters, used for a personal app; check the rights before ever publishing it. Both voices live in src/lib/coach.ts. coachMessage(days, logged, seed, today, voice, ctx) collects every situation that is true right now (24 situations, about 160 Goku lines and about 170 Mirko lines: workout state, time of day, week progress, days since the last workout, protein, water, food logged, sleep, weight moving toward or away from the goal, a random wildcard), weights the main workout situation highest and picks with the seed. The Dashboard builds the CoachContext from the store, re-rolls the seed every 10 minutes with the quote, and when the speech bubble is tapped. Mirko has the same 24 situations (about 170 lines) in her own soft, motivating voice, so both react to progress the same way; add lines to MIRKO or GOKU in the same Line format to extend them, and every situation must exist in both. Placeholders in lines: {n} streak, {m} missed in 7 days, {t} total workouts, {d} days since the last workout, {w} and {p} workouts done and planned this week, {kg}, {pct}, {prot}, {h}. Test the engine by transpiling coach.ts with typescript and sweeping seeds; check for unfilled placeholders and dashes. Both voices stay about effort and never body or identity, and use no dashes in the copy. src/components/CoachCharacter.tsx shows the picture whole (never cropped or stretched, sized from each image's ratio) in their own colours on the black card (no filter, no rim light, no glow or background). Both breathe. Goku bounces when pleased and shakes with an anger mark and shout lines when you skipped. Mirko only floats softly and sways, never shakes. All motion stops when reduce motion is on. The coach card stays black and white: the small name label is a softer white (C.soft) above the pure white title, in the display font, never green or cream. CoachCard.tsx shows it with a speech bubble and a Try button to swap; the User page has a Your coach picker.
- Testing pages without the real database: build with `npx expo export --platform web --output-dir <dir>`, serve it, and use Playwright (playwright-core with the installed Chrome) with Supabase requests faked by an in memory database. The project does not include Playwright.

## User preferences (follow these)
- Keep the pure black and white theme, with muted accent colours for labels, charts, nutrients and groups. Do not change the base theme.
- No dash or hyphen punctuation in UI copy. Use commas or colons instead.
- Plain, simple language; beginner friendly; direct replies; simplest solution that works.
- Height in cm or ft/in; weight typable plus steppers; decimals allowed (e.g. 5.5 work hours).
- Body stats: height, weight, goal weight, date of birth, sex, job type (with descriptions and examples), optional weekly or per day work hours.
- Amir's own goal is "Lose fat and build muscle" (recomp): calorie deficit with high protein.

## Saving the profile
