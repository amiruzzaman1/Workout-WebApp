# Workout WebApp: project context for Claude

Personal workout, food and habit tracker. Built for Amir (complete beginner, trains at Jetts Newtown, Wellington NZ) and one friend. Each has their own account and plan. Not published to app stores. Web first; Android/iOS later via Expo Go.

## Stack
- Expo SDK 57, expo-router, React Native Web, TypeScript. Run: `npm run web` (clean cache: `npx expo start --web -c`). Build: `npx expo export --platform web` (output: dist).
- Supabase (auth + Postgres). Project ref `zglxidulxgjfschsrvqm`, URL https://zglxidulxgjfschsrvqm.supabase.co. Client uses the publishable key in `src/lib/supabase.ts`. Never use or commit the service_role key.
- Every table has RLS: `(select auth.uid()) = user_id`, granted to `authenticated` only (automatic table exposure is off). Full schema with versioned sections v1 to v10 in `supabase/schema.sql`; append new changes as a new vN section.
- Hosting: Vercel project `workout-webapp` (vercel.json has SPA rewrite). GitHub repo amiruzzaman1/Workout-WebApp, pushed from GitHub Desktop.
- Shared foods (v10, table shared_foods): foods users add by hand are visible to every signed in user, anyone can edit them, the database records who added and who last edited (trigger), only the creator can delete. The app shows Added or Edited by you or someone else, your own first, with a caution warning on user added foods. Duplicates by name are allowed.
- Data sources: free-exercise-db (public domain images), Open Food Facts (NZ barcodes and search, `src/lib/off.ts`). Typing one or two words first runs a brand search (brandSearch() in off.ts, the newer service's `brands:word*` filter, the last word as a prefix so "collec" already lists The Collective, sold in NZ first), and products whose brand matches what you typed are listed ahead of the rest; Open Food Facts allows about 10 searches a minute, so a brand search that fills the list stops further requests. Search matches each typed word against name, brand, generic name and category (all spellings of yoghurt count as one word, since a real product, The Collective's Epic Greek, is named without "yogurt" and only filed under Greek yogurts); with 3 or more words and fewer than 5 exact matches it also lists products missing one word, and the newer search.openfoodfacts.org service is asked whenever the classic one is down or came up short (it sends brands as a list, not text, and some products there carry only energy-kj_100g, so fromOFF() falls back to kJ divided by 4.184 or those products had 0 calories and were dropped). Every food's energy is written with both units, kcal first and kJ in brackets, "105 kcal (439 kJ)": always print it with fmtEnergy() (or toKJ() for a split layout) in nutrition.ts (KJ_PER_KCAL 4.184), never kcal alone. Used on search rows, the portion screen (with the per 100 values to check against a label), the Food tab total, each meal and logged item, recipes (list, builder, ingredient lines) and the voice command confirm lines; Quick add has a kcal/kJ switch so a label's kJ can be typed directly, still stored as kcal. Scanning (src/components/BarcodeScanner.tsx): web uses the browser's BarcodeDetector (Chrome/Android; iOS Safari falls back to typing the barcode); the Android/iOS app uses expo-camera's CameraView/useCameraPermissions instead, a real native camera module, so the native app always has a working scanner regardless of what the web branch can do (fixed a bug where the native app always showed the "browser can't use the camera" fallback because the supported check was web-only).
- Avoid adding native libraries without telling the user to install them; `react-native-svg` is in package.json and installed, and the Dashboard summary rings use it (LineChart is still plain Views).

- food: index (daily log, macros, water, meal summaries), add (search, scan, my foods, quick add, portion with % of daily targets), nutrition (body stats, BMI, burn breakdown, calorie and macro targets). A food's `unit` is `g`, `ml`, or `piece` (a whole item counted as 1, 2, 3, such as a kebab or a slice, no weight needed); Quick add has a By weight / Whole item choice, and By weight also has a g/ml/kg/L choice for the label's numbers (kg and L are converted down to per 100 g/ml on save, so storage never changes). The Portion screen mirrors this: a piece food asks "How many?" with whole item chips, a weight food keeps its g/ml amount box but can switch to kg/L next to it (the number shown converts, so 500 g becomes 0.5 kg). Sugars and saturated fat are not separate amounts, they are part of carbs and fat (the label's "of which" lines), so Quick add draws each as a smaller, indented `SubField` connected to its Carbs or Fat box with a corner line and labelled "optional", instead of sitting in a plain grid where it would look just as required as the macro above it; fibre and sodium (not part of anything else) stay in the separate "More nutrition" collapsible. `scaleFood()` and `fmtAmount()` in src/lib/nutrition.ts are unit aware; never scale or display a Food or FoodEntry's amount without them. My measures (table food_measures, schema v20; store.tsx's foodMeasures/saveFoodMeasure/deleteFoodMeasure, FoodMeasure and measureKey() in nutrition.ts): on the Portion screen of any g or ml food you can save your own measure ("1 teaspoon = 3 g", name plus how many g/ml one is), kept per food name (lower case, so it follows the food whether found by search, scan or My foods) on your account so it syncs between web and Android. Not offered for whole item (piece) foods, which are already counted. Delete a measure with its button while it is picked.

VoiceCommand.tsx also has a plain text box next to the mic, for a typed instruction instead of a spoken one; both go through the exact same pipeline. The model's own loading and inference were not testable from this environment (no Android device here); only the surrounding TypeScript was. The native download in expo-llm-mediapipe@0.6.0 has no read timeout, so a connection that stalls after connecting (dead redirect, CDN hiccup, flaky mobile network) hung forever at 0% with no error and no way out; patched via patch-package (patches/expo-llm-mediapipe+0.6.0.patch, postinstall: patch-package in package.json): a 30 second read timeout turns a stall into a catchable error (the existing error UI on app/(tabs)/user/ai.tsx already handles that), and Cancel now actually closes the socket (activeConnections map, connection.disconnect()) instead of only flipping a coroutine flag that a blocked read never checks again. ai.tsx also has a client side watchdog (progress unchanged for 25s) that shows a Cancel button early, before the native timeout would otherwise fire. If the in-app download still will not finish (a flaky connection beats even the 30s timeout repeatedly), app/(tabs)/user/ai.tsx has a manual fallback: "Open the download link" (Linking.openURL(MODEL_URL), the user's own browser downloads the same file, usually far more reliably than this app's downloader) and "Use a file I already downloaded" (ai.importLocalFile() in aiRuntime.android.tsx, expo-file-system's own File.pickFileAsync() system file picker, copied into Paths.document + 'llm_models/' + MODEL_NAME, the exact folder and filename expo-llm-mediapipe's own "already downloaded" check looks at). Since useLLM() only checks disk once, on first mount, aiRuntime.android.tsx wraps the hook in a remountable LlmBridge keyed by a generation counter, bumped after importLocalFile() or remove(), so the runtime notices the file without restarting the app. The mic button (VoiceCommand) is mounted once in app/(tabs)/_layout.tsx, a sibling of the Tabs navigator rather than inside any one tab's own screen, so it floats on every page in every tab, not just the Dashboard. It can also talk back (src/lib/speech.ts, expo-speech, Android's own text to speech, off by default): a speaker icon in the top left of the voice modal (always there, every phase) turns it on or off, persisted the same way as the AI toggle. When it is on, VoiceCommand speaks a short line at the same two moments the modal already changes to show something, understanding a command (speakable(intent), kept in sync with ConfirmCard's own text) and the result (done or the error message), never a running narration of everything typed or heard. Loading an already downloaded model into memory (as opposed to downloading it) had the same silent hang bug as the download once did: the automatic load in aiRuntime.android.tsx's effect caught its own failure and did nothing with it, so a genuine failure (a corrupt or incomplete manually imported file, not enough memory) looked identical to "still loading" forever. Fixed: load failures now set loadError, surfaced on app/(tabs)/user/ai.tsx with a Try again button (ai.retryLoad()); that screen also times how long it has been loading (the first load after a fresh download or a manual import can genuinely take a couple of minutes while MediaPipe sets up its GPU delegate) and says so past 20 seconds, instead of leaving a bare "Loading..." with no sense of whether it is normal or stuck. That error surfacing is what then caught a real, unrelated problem on the real device: Gemma 3n (gemma-3n-E2B-it-int4.task) failed to load with "Unsupported model signature" from odml.infra.LiteRTResourceCalculator, because Google only ever shipped Gemma 3n for the LLM Inference API in the newer .litertlm container, never the Task Bundle (.task) format this library (com.google.mediapipe:tasks-genai, now in maintenance mode) understands, so no download or code fix here could have made that file load. Swapped to Gemma 3, the smaller 1B model, which Google does ship as a real .task file for this exact API (litert-community/Gemma3-1B-IT): MODEL_NAME and MODEL_URL in src/lib/aiAssistant.ts now point at gemma3-1b-it-int4.task (an ungated mirror of that same official file), MODEL_SIZE_MB (560) replacing the old MODEL_SIZE_GB. Getting the model to load was not the end of it: the app crashed outright (not a JS error, the whole process, "it shuts down") the moment a command actually reached the model. maxTokens (the model's whole session budget, prompt and reply together, fixed once at load time) was 256, but aiAssistant.ts's own written contract (systemPrompt()) with a realistic number of foods and exercises filled in comes to roughly 900 tokens on its own, so every real request already overflowed the native engine's buffers before it could even reply, which on this engine is a native crash, not a catchable error. Fixed by raising maxTokens to 2048 in aiRuntime.android.tsx's useLLM() call (the one place it is set, used for both loading and generating since the native session is sized once at creation), with todayTasks and reminders in systemPrompt() now also capped at 30 each (foods and exercises were already capped) so one very full day cannot push it over again.

Also fixed: voice commands for going to bed or waking up ("I woke up at 11:30") were silently ignoring any clock time actually said and always using the current time instead, since the code simply never looked; parseVoiceCommand's sleep_start/sleep_end now call parseTime() on what was heard and only fall back to nowClock() when no time was stated. This needed norm() to stop stripping the colon out of a stated time first, since "11:30" was becoming "11 30" (losing the minutes) before parseTime() ever saw it; colon joins the decimal point in norm()'s allowed characters. The AI model's own sleep_start/sleep_end now accept the same optional time for consistency, though the free word matching above normally catches these phrases first.

More than one action in one sentence ("add a task to call the dentist and start my study timer") now works too, not just the single action each phrase above describes on its own: VoiceIntent has a 'multi' kind ({kind,intents}), and parseVoiceCommand in voiceParse.ts is now a thin wrapper around the original single-command matcher (renamed parseSingle, no longer exported): it tries splitting the sentence on "and then", "then", "and also", then bare "and" (checked in that order so the more specific ones win), and only actually commits to two commands if each half, parsed completely on its own, resolves to something real; otherwise, since one or both halves came back unknown, it is treated as not a real split and the whole sentence is parsed as one command as before. That check is what keeps an "and" that is genuinely part of one phrase ("remind me to call mum and dad", deleting "the eggs and bacon" entry) from being wrongly cut in half: either half alone would be unknown, so the split is rejected. Recurses on the right half so three or more chained actions flatten into one 'multi' rather than nesting. hasDestructive(intent) (also exported from voiceParse.ts) looks inside a 'multi' for the stronger delete confirmation, since isDestructive(kind) alone cannot. In VoiceCommand.tsx, act() loops a 'multi' through itself, speakable() joins each sub-intent's own line, and ConfirmCard's old per-kind body is now IntentBody, reused once per row for a 'multi' (with a thin divider between rows) or once for a single command as before.
